# Hackathon submission checklist

The authoritative requirements are the [Devpost rules](https://nebiusglobalaihackathon.devpost.com/rules). Verify them again before submitting.

- [ ] Make a reviewed source repository public and open source, with its license visible and setup instructions available. The current remote was private when this checklist was prepared; do not expose keys, private data or `.oriclus/` history.
- [ ] Provide a judge-accessible working demo or test build and instructions. The local server runs trusted repository code and is restricted to loopback; do not expose it directly to the public internet. A source archive without credentials requires the tester to configure their own Nebius credentials and does not by itself prove unrestricted judge access.
- [ ] Record a demonstration under three minutes and publish it on YouTube. [Demo script](demo-script.md) identifies which observations are real and which are limitations. A script is not a recorded video.
- [ ] Choose the Coding and Agentic Engineering track, explain the Sandbox, Nemotron and Tavily runtime roles, provide required feedback, and accurately describe any prior-project changes.
- [ ] Verify the evidence links and commands in [evaluation cases](evaluation-cases.md). Local run IDs are not shipped with the source archive.
- [ ] Obtain actual maintainer feedback before making claims about user time saved; do not invent interview results. The tested uv comparison and other measurements must be reported with scope and limitations.

Do not claim a perfect score. The project has not been validated across arbitrary private repositories, enterprise environments or every package-manager configuration.
