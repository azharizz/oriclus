# Oriclus

## Platform
web

## Stack
React is required by the user. FastAPI and SQLite are the implementation choice for the local execution service.

## Users
Python library maintainers rehearsing an upstream change against downstream repositories before release.

## Product Purpose
Trace a change through real consumer tests and inspect model-authored, independently verified migration patches.

## Operating Context
A local, single-operator engineering workspace. Public GitHub source, configured Nebius inference and Tavily source research, Docker filesystem snapshots pending ConTree access. No published PRs or hosted service.

## Capabilities and Constraints
Repository-first discovery proposes one to three public Python consumers using the configured model, Tavily and inspected GitHub source. Review the proposal before any repository code runs. Optional manual setup supports up to ten consumers. Real baseline and candidate executions, an evidence ledger with source citations, isolated repair candidates, patch export, cancellation and durable history follow review. Keep the default form to a required repository and an optional change ref; show outcomes first and expose details on demand. Paginate long result and evidence lists. Tests provide bounded evidence, never a universal release guarantee. Python-first follows the supplied brief. Model explanations are advisory; original tests and independent verification determine execution status. User delegated completion while away, so implementation and visual decisions proceed without an approval ceremony. Work solo.

## Brand Commitments
Name: Oriclus. No em dashes. Clear engineering language. No fabricated results, integrations, or claims. The user selected Nebius Token Factory's desktop visual template: Inter, charcoal surfaces, purple controls, compact sidebar and an outlined wordmark. Oriclus keeps an original lime and mint cycle mark. See DESIGN.md for implemented tokens. Desktop is the current review scope.
